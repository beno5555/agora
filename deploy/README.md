# Hosting

How Agora runs on its public host, and how to set it up and deploy. Decided on 2026-10-13 (Sandro).

```
browser ──https──▶ Caddy (:443, Let's Encrypt cert) ──http──▶ Agora app (localhost:8080) ──▶ SQLite /var/lib/agora/agora.db
                   on a DigitalOcean droplet                  API + Angular build, one process  └─▶ Helius devnet RPC
```

| Decision | Choice | Why |
|---|---|---|
| Provider | DigitalOcean droplet, Basic $6/mo (1 GB RAM), Ubuntu 24.04, Frankfurt | Simple, instant signup. Billing is hourly, so the $5 credit covers about 25 days. |
| Address | `https://<ip-with-dashes>.sslip.io` (e.g. `203-0-113-5.sslip.io`) | No domain to buy. sslip.io resolves the name to the IP. HTTPS is required: the session cookie is `Secure`. |
| Reverse proxy | Caddy | Gets and renews the HTTPS certificate on its own; the config is 3 lines. |
| .NET | Self-contained publish (`-r linux-x64 --self-contained`) | The runtime ships inside the app folder, so the server needs no .NET install. Everything is built on the dev PC; the server only runs the result. |
| Process | systemd service `agora`, `Restart=always` | Survives crashes and reboots. |
| Database | SQLite, kept | One process on one server at demo scale. The file lives outside the app folder, so deploys keep it. |
| Secrets | `/etc/agora/agora.env` on the server, root-only | Generated by `deploy.ps1 -Setup`. Never in git. |
| CI/CD | None: `deploy.ps1` from the dev PC | Not worth it before the deadline. |

## Files here

| File | What it is |
|---|---|
| `deploy.ps1` | Run on the dev PC. Builds the frontend and backend, uploads, restarts, checks `/health`. `-Setup` first sets up a fresh droplet. |
| `setup-server.sh` | One-time server setup, run by `deploy.ps1 -Setup`: swap, Caddy, firewall, the `agora` user and folders, the service, the secrets file. |
| `install-release.sh` | Run by `deploy.ps1` on every deploy: swaps in the new release and waits until it's healthy. |
| `agora.service` | The systemd service. Non-secret settings are here. |
| `Caddyfile` | The Caddy config (`AGORA_HOST` is filled in by `setup-server.sh`). |

## One-time setup

### 1. SSH key (on the dev PC)
If `~/.ssh/id_ed25519.pub` doesn't exist yet: `ssh-keygen -t ed25519` (press Enter through the questions).

### 2. Create the droplet
DigitalOcean → **Create → Droplets**:
- **Region:** Frankfurt (FRA1). **Image:** Ubuntu 24.04 (LTS) x64.
- **Size:** Basic → Regular → **$6/mo** (1 GB / 1 CPU / 25 GB SSD).
- **Authentication:** SSH Key → New SSH Key → paste the contents of `~/.ssh/id_ed25519.pub`.
- **Hostname:** `agora`. Leave backups, monitoring and the other add-ons off.

Copy the droplet's **public IPv4** address once it's created.

### 3. First connection
```powershell
ssh root@<ip>    # answer "yes" to the fingerprint question, then type: exit
```

### 4. Set up and deploy
From the repo root, in PowerShell 7, with `$env:Solana__RpcUrl` set to the Helius devnet URL (it already is on Sandro's PC):
```powershell
./deploy/deploy.ps1 -Server <ip> -Setup
```
It takes a few minutes. It ends with `Deployed: https://<ip-with-dashes>.sslip.io`.

## Every later deploy
```powershell
git pull --rebase
./deploy/deploy.ps1 -Server <ip>
```
Stop `ng serve` first: `npm ci` replaces `frontend/node_modules`. The app is down for a few seconds while it restarts. The database is kept.

## Check that it works
From a phone on mobile data, not the dev PC:
- `https://<host>/health` and `https://<host>/api/config` return 200.
- Sign in with Phantom: no domain warning, and the session survives a reload.
- Two devices signing in at about the same time don't get `429` (proves the per-IP rate limit sees real client IPs).
- The demo path: list → buy → accept → deliver → confirm, and the `2m` missed-deadline refund.

## On the server
```bash
ssh root@<ip>
systemctl status agora            # is it running?
journalctl -u agora -f            # app logs (Ctrl+C to stop)
journalctl -u caddy -n 50         # certificate / proxy problems
systemctl restart agora
nano /etc/agora/agora.env         # secrets and host; then: systemctl restart agora
```
Copy the database to the dev PC (stop the app first so the copy is consistent):
```powershell
ssh root@<ip> systemctl stop agora; scp root@<ip>:/var/lib/agora/agora.db* .; ssh root@<ip> systemctl start agora
```

## Troubleshooting
| Symptom | Likely cause |
|---|---|
| Phantom warns that the domain doesn't match | `Auth__Domain` in `/etc/agora/agora.env` isn't exactly the page's host. |
| Browser shows a certificate error, or `/health` times out right after setup | Caddy is still getting the certificate, or failed: `journalctl -u caddy -n 50`. Ports 80 and 443 must be open (`ufw status`). |
| `502 Bad Gateway` | Caddy is fine but the app isn't running: `journalctl -u agora -n 50`. |
| Sign-in works but you're signed out on reload | The page isn't on HTTPS (the cookie is `Secure`). |
| `400 Bad Request` on every page | The host isn't in `AllowedHosts` in `/etc/agora/agora.env`. |
| `deploy.ps1` fails at `npm ci` with `EPERM` | `ng serve` (or an editor) is holding files in `node_modules`; stop it and rerun. |
